From your prompt to an open MR

Every step between typing a feature request and getting a merge request, with the rule each step follows. The agent does the work; gate.py decides what gets reviewed and checked and whether it passed; the hooks refuse a commit or push that lacks a passing stamp. Merging is always yours.

The prompt

You
/parallel-feature-workflow gated
slug: export-csv
feature: Add a CSV export to the results page. Default delimiter is a comma;
the button sits next to "Download JSON". Out of scope: Excel files.

With gated

The word is your authorization. A passing plan gate replaces your plan approval, and passing gates authorize the commit, the push and opening the MR. The flow runs to the MR and stops only when a step uses all its attempts.

Without gated

The same gates run, but the flow stops for you twice: after the plan review (you approve with #approve-plan) and before the commit (you get a proposed message and say go).

Why the wording matters. The feature: text is saved word for word as request.md, and every reviewer checks the work against it. A vague ask makes vague checks. The Out of scope: line is how reviewers tell your intent apart from the agent's additions.

Pre-flight

Agent

Make sure the repo is safe to branch from before anything is created.

  1. The main checkout must be clean (git status), and the agent must not be on a branch it would commit to.
  2. git check-ignore on a path inside .worktrees/, .venv and .env. If .worktrees/ is not ignored, it goes into .git/info/exclude (local, no commit), and the permanent .gitignore line ships on the feature branch.
  3. Once per clone: push.default current and push.autoSetupRemote true, so a push from a worktree goes to its own branch, never to the base.
  4. The project file (.claude/parallel-feature-workflow.md) is read; its ## Pre-flight steps run.
  5. Waits for "OK START DO IT". A gated request counts as that go-ahead.
Produces
A clean, ignore-safe repo
Stops when
The tree is dirty, or waiting for your go (not gated)

Worktree + venv

Agent

One isolated checkout per feature, so features never touch each other or main.

  1. git fetch origin, then git worktree add --no-track .worktrees/<slug> -b feat/<slug> origin/<base>.
  2. Checks the new branch has no upstream. With one, the branch would track the base and a later push could land on it.
  3. Creates a fresh .venv inside the worktree and installs there. This standing answer replaces "which venv?" questions.
  4. Copies the files the project lists (## Copy into worktree) and links heavy dependency folders such as node_modules (## Link from main), never installing through a link.
  5. Runs the project's ## Setup.

Why origin/<base>, not the local branch. A local branch is often behind; basing on it silently builds the feature on stale code.

Produces
.worktrees/<slug> on feat/<slug>, own venv

Register the run

Agentgate.py

Write down the three artifacts everything after this is checked against.

  1. request.md: your feature: text, verbatim.
  2. plan.md: the plan, opening with its file table (every file it will create or change).
  3. divergence-log.md: empty for now; every departure from the plan goes here.
  4. gate.py init --request … --plan … --divergence-log … registers the run for the branch and prints the dashboard path (plus the Windows path under WSL). The dashboard reloads itself. Its top box says that reviewers are running, that everything passed (each stage's stamp), that it passed but the agent set serious problems aside, that older bugs need your decision, or why a stage did not pass, one line per blocker; the last three list the replies you can type.

Why it is files, not chat. Reviewers read these exact files. A long session gets compacted; the files survive it, and the fidelity reviewer can compare the code with what you asked and what was planned.

Registered run + live dashboard

Plan gate

gate.pyReviewersAgentYou (not gated)

A reviewer checks the plan before a single line of code is written.

  1. plan-prepare tiers the plan from its file table and writes the plan reviewer's prompt. A docs-only plan gets no reviewer.
  2. The plan reviewer runs in a fresh read-only worker and checks P1–P7: coverage of the request, traceability, proportionality, reuse of existing code, the consumer sweep (every file that reads what changes), project rules, and unproven claims.
  3. plan-ingest verifies each finding's quote sits at the cited line, else drops it.
  4. Findings: the agent revises the plan, or rejects a wrong finding with a file:line citation.
    • Gated: back to step 1. No human reads the plan, so a reviewer re-checks the fix.
    • Not gated: no second round. You see each finding next to the plan text that fixes it and type #approve-plan.
  5. The plan stamp is written. It also writes HANDOFF.md and moves the request, plan and log into .handoff/; the agent asks "build here, or in the worktree's own window?" (there you type /resume-handoff).

Why review the plan first. A missed consumer or a disproportionate design is cheapest to fix as one sentence of plan, not as code across ten files.

Produces
Plan stamp (PASS or APPROVED), handoff
Stops when
2 failed rounds, or waiting for #approve-plan

5

Implement

AgentReviewers (tripwire)

implement-plan builds the plan end to end without stopping to ask.

  1. Lock the plan. Turn its steps into a checklist, record the base commit and the files that were already dirty (those are not reviewed), and start the divergence log.
  2. Build with TDD, reading each file before editing it and matching the code around it.
  3. Log every divergence instead of asking. [LOGIC] = behavior, output or file set changed (with the rejected alternative); [MECH] = naming, placement, additive work; [RULE] = a change made because a reviewer found something.
  4. Tripwire. Right after the first edit to a risky file (one in the gates' always_when), the project reviewers for that file run once. No attempt is counted and no stamp is written; the point is to catch a bad first instance before it is copied nine times.

The only hard stops here: a destructive, irreversible or outward-facing action, or a plan that has become impossible with nothing independent left to do. A preference question is never a stop; it becomes a [LOGIC] row you read in the summary.

Produces
The code, tests, divergence log
Stops when
Only on the hard stops above

Review gate

Agentgate.pyReviewers

Independent reviewers, each with one lens, read the exact staged tree. The script, not the agent, decides who runs and whether it passed.

  1. Stage by name. git add <explicit paths>; -A, ., -u and directories are blocked.
  2. Select. review-prepare picks reviewers from the diff against the merge-base (see What runs, and why) and skips any reviewer still clean for its scope.
  3. Dispatch. Every selected reviewer starts at once in a fresh read-only worker, at its model tier. Its prompt is one line pointing at the file gate.py wrote; the agent adds nothing, summarizes nothing.
  4. Save verbatim. Each reply is saved unchanged to its out file before anyone acts on it.
  5. Ingest. review-ingest drops a finding whose quote is not at the cited line, and marks a reviewer invalid if it skipped a file in its scope or reported the wrong tree.
  6. Triage. Each open finding is verified against the code: fixed, or rejected as wrong with gate.py reject --cite file:line. Each finding can be rejected only once: if the reviewer raises it again, it keeps blocking until it is fixed or the attempts run out and you decide. Each outcome is noted on the dashboard in plain English.
  7. Re-stage and repeat until clean, then stamp --stage review.

The rules that keep rounds short

One roundEvery selected reviewer runs together, so one fix never starts a separate round for the others.
ExclusionsA reviewer never sees files its lens exempts: test files never reach polish or data-schema.
Delta re-reviewA reviewer that already reviewed this branch gets only what changed since, plus its own still-open findings to re-check. It reads the changed parts of each file, reports only what those changes break, and runs at the standard model at most. The first review covers the whole change, reading each file end to end.
Real defects blockA blocker or should-fix stops the commit. A nit (naming, constants, style, duplication) is listed and never does. An older bug the change did not cause costs no attempt and waits for your decision.
No new scopeOn a re-review, a new should-fix on unchanged lines, older or not, is kept as a non-blocking nit. A blocker always stands, and so does an old finding that is still not fixed.

Plus re-run only where needed: once clean, a reviewer with rerun_skip = ["@tests"] is not re-run when only tests changed, so a test-only fix re-runs the tests reviewer alone.

Produces
Review stamp for the staged tree
Stops when
3 failed rounds (blocking findings or an invalid reviewer)

Checks gate

gate.pyAgent

The project's real commands run against the tree. Starts in the background alongside the review round.

  1. checks-run runs every selected check not already passing for this tree, in order: mechanical → unit (targeted) → dry run → UI → real → full suite. A failure stops the later groups.
  2. Real checks run only if the project's max_usd is above 0; otherwise they are SKIPPED and listed as unverified.
  3. The full suite (last = true) runs once and must pass on exactly the final tree.
  4. A red check: read its log and fix the code. --baseline <id> re-runs it on a clean base worktree to say whose failure it is, but it still blocks either way.
  5. Then stamp --stage checks.

Never weaken a check. No skip, xfail, loosened assertion, deleted test or mocked-away unit to get green. A test failing because the code is wrong is the test doing its job.

Produces
Checks stamp, evidence logs
Stops when
3 failed runs

Commit

AgentHookYou (not gated)

The hook lets a commit through only with both stamps for the exact staged tree and clean hygiene.

  1. Before: the interpreter resolves inside the worktree; only files the agent created get formatted (an edited file only if it was clean at HEAD); gate.py status shows both stamps.
  2. Gated: git add <paths>, then a plain git commit as a separate command. One concept per commit, compact subject. Not gated: the agent stops, summarizes, proposes the message and waits.
  3. The hook checks the review and checks stamps for HEAD^{tree} of the staged index, then hygiene (no model, seconds):
RuleBlocks when
H1 unplanneda staged file is in neither the plan's file table nor the divergence log
H2 junka staged file matches the junk patterns: scratch dirs, logs, .bak/.orig/.rej, caches, run outputs
H3 scratch leakan added line contains a scratchpad or temp path
H4 heavya binary file, or one over max_file_kb, that the plan does not list
H5 leftoversreport only: untracked files, listed for cleanup

Also blocked: git commit -a, commits with pathspecs, staging and committing in one command, a commit and a push in one command, and gated git commands hidden behind a wrapper such as timeout or env. Your own terminal is never gated.

Produces
A commit on feat/<slug>
Stops when
Blocked until fixed; a code fix re-runs the touched review and checks

Push gate + MR

gate.pyHookAgent

One last audit over every commit on the branch, then the MR is opened. It is never merged.

  1. Confirms there is something to send: git log origin/<base>..HEAD is not empty.
  2. audit --mode branch --fetch checks every commit: hygiene H1–H4, forbidden paths (.env, keys, agent folders), and secret patterns.
  3. If the base moved under the branch, the affected checks re-run on the merge result. A merge conflict uses up all push attempts at once, because only a rebase can fix it and that is yours to do.
  4. stamp --stage push. The hook re-checks every stamp for HEAD^{tree} before letting the push through.
  5. Push with an explicit refspec (git push -u origin feat/<slug>), never a bare git push, then open the MR (GitLab push options, or gh pr create).
  6. The MR body: implement-plan's summary (decisions made for you, what was built, how it was tested, the review rounds, gaps), then gate.py summary --head: the reviewers with why each ran, and How it was tested.
Produces
Push stamp, the MR URL
Stops when
2 failed audits, or a conflict with base
Then
Merge is yours

Model tiers are agent-neutral: in Claude Code, light = haiku, standard = sonnet, strong = opus. Each reviewer is proven once by /gate calibrate (it must catch a planted defect and stay quiet on a clean case) after its own files or model change; an uncalibrated reviewer still runs, with a warning.

The one stop rule

The flow stops and waits for you only when a step has used all its attempts, with the two exceptions below. An attempt is a failed run; a run that passes costs nothing. In a review each reviewer has its own count, five by default. You get what each attempt tried and the open findings or the failing log tail, and reply with one of:

#accept-gateContinue; the open findings are listed in the MR.
DirectionTell the agent what to do; the step gets fresh attempts.
#abortStop here.

Two exceptions, tries left or not. The agent set aside a serious code-review finding whose quoted text is still in the file: you reply fix them or leave them. A reviewer found an older bug the change neither caused nor worsened: you reply fix them or #accept-gate.

Never a stop: a real run with max_usd = 0 (it is SKIPPED and reported unverified). Always a block: a failing test, even one that also fails on base.

Your tags

One-shot, bound to the session, expire after 2 hours. Only your typed prompt can arm one: the agent cannot write the token files, and text relayed from a reviewer or a notification never arms a tag.

TagEffect
#approve-planNot gated: approves the plan as fixed after its one review round, without a re-review.
#accept-gateA gate stopped at its cap is stamped ACCEPTED; the MR lists what was open. A secret is never let through.
#skip-reviewThe next commit and push skip the reviewer rounds; checks and hygiene still run.
#skip-gatesThe next commit and push skip review, checks and push stamps; hygiene and secrets still run.

Limits

  • Every session ends with How it was tested from gate.py summary --tested: each kind that took part, then one line for what is missing, with why. The divergence log's rows are on the dashboard only.
  • Stamps prevent omission, not forgery. A determined agent could fabricate reviewer output; the MR links the raw outputs so you can spot-check them.
  • Reviewers are models. Calibration proves a reviewer can see a planted defect, not that it saw every real one.
  • Real-LLM output quality always needs your eyes.
